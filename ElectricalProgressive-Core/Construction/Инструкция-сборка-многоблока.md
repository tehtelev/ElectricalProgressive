# Подключение многоблочной машины к сборке из компонентов

Core сам вешает поведение `MachineConstruct`, если у блока контроллера есть `attributes.construction.levels` и задан `entityClass`. Книга чертежей ставит вариант `incomplete`. Игрок кликает по любому куску структуры с ресурсом текущего этапа. Последний этап меняет блок на `formed` и заново ставит multiblock.

Рабочий пример: `ElectricalProgressive-Industry/assets/electricalprogressiveindustry/blocktypes/ehammer.json` и `Content/Block/EHammer/BlockEHammer.cs`. Мод машины зависит от `electricalprogressivecore`.

Поведение `MachineConstruct` в `entityBehaviors` и `behaviors` не пишется. Его добавляет `MachineConstructSystem` на `AssetsFinalize`.

## 1. JSON контроллера

Нужны `class`, `entityClass` и вариант `state`. Без `entityClass` в логе будет `has construction.levels but no entityClass`, сборка на блок не встанет.

```json
"variantgroups": [
  { "code": "state", "states": [ "incomplete", "formed" ] },
  { "code": "side", "loadFromProperties": "abstract/horizontalorientation" }
],
"creativeinventory": {
  "general": [ "*-formed-north" ],
  "electricity": [ "*-formed-north" ]
}
```

В креативе только собранный северный вариант. Чертёж ставит книга, не предмет из инвентаря.

В `behaviors`:

- `HorizontalOrientable` с `"handleDrop": false` — при сломе не падает сам блок.
- `BlockEntityInteract`.
- `Multiblock`. Маски `*-north`, `*-east`, `*-south`, `*-west` покрывают и `incomplete`, и `formed`: призрак занимает тот же объём, что и готовая машина. `cposition` — клетка контроллера внутри этого объёма.

Секция сборки:

```json
"construction": {
  "brokenDropsRatio": 1,
  "blueprintShape": "block/mymachine/mymachine",
  "levels": [
    {
      "shape": "block/mymachine/mymachine_base",
      "actionLangCode": "mymod:mymachine-handbook-place-controller"
    },
    {
      "shape": "block/mymachine/mymachine_base",
      "actionLangCode": "mymod:mymachine-construct-frame",
      "requireStacks": [
        { "type": "item", "code": "game:metalplate-steel", "quantity": 8 }
      ]
    },
    {
      "shape": "block/mymachine/mymachine",
      "actionLangCode": "mymod:mymachine-construct-finish",
      "requireStacks": [
        { "type": "item", "code": "game:metalplate-copper", "quantity": 4 }
      ],
      "formMachine": true
    }
  ]
}
```

Пути шейпов считаются от домена блока: `block/mymachine/mymachine` → `assets/<modid>/shapes/block/mymachine/mymachine.json`. Шейпы рисуются для севера. Поворот по `side` делает сборка, отдельные шейпы на восток и запад не нужны.

Пока не сдан ни один ресурс, клиент рисует синий призрак полной модели (`blueprintShape`). После каждой сдачи виден `shape` этого этапа. Нулевой уровень без `requireStacks` — постановка контроллера, в справочнике он не показывается. У последнего уровня `"formMachine": true`: блок меняется на `state=formed`, затем вызывается `Multiblock.OnBlockPlaced`, и dummy пересобираются уже как готовая машина.

`shapebytype`: `*-incomplete-*` — шейп первого этапа, `*-formed-*` — полная модель.

Цвет призрака по желанию:

```json
"blueprint": { "fillR": 75, "fillG": 135, "fillB": 190, "fillA": 255 }
```

Сетку крафта этой машины убрать. Раздел «Сборка» в справочнике строится сам из `levels`.

`brokenDropsRatio: 1` возвращает все сданные ресурсы. Сама машина не выпадает.

Книга показывает машину, если есть `construction.levels`, вариант `state=incomplete` и сторона `side=north`. В список попадает один блок на `домен:первое-имя-кода`.

## 2. Класс блока

Класс реализует `IMultiBlockInteract`. Клик по dummy не попадает в поведение контроллера, поэтому сборка идёт через позицию контроллера. Образец — `BlockEHammer`.

```csharp
using MachineConstruct = global::ElectricalProgressive.Construction.BEBehaviorMachineConstruct;
using MachineConstructAccess = global::ElectricalProgressive.Construction.MachineConstructAccess;

public class BlockMyMachine : Block, IMultiBlockInteract
{
    public override bool OnBlockInteractStart(IWorldAccessor world, IPlayer byPlayer, BlockSelection blockSel)
    {
        if (blockSel == null || !world.Claims.TryAccess(byPlayer, blockSel.Position, EnumBlockAccessFlags.Use))
            return false;
        return HandleInteract(world, byPlayer, blockSel.Position, blockSel);
    }

    public bool MBOnBlockInteractStart(IWorldAccessor world, IPlayer byPlayer, BlockSelection blockSel, Vec3i offsetInv)
    {
        if (!world.Claims.TryAccess(byPlayer, blockSel.Position, EnumBlockAccessFlags.Use))
            return false;
        var controllerPos = MachineConstructAccess.GetControllerPos(blockSel.Position, offsetInv);
        return HandleInteract(world, byPlayer, controllerPos, blockSel);
    }

    private bool HandleInteract(IWorldAccessor world, IPlayer byPlayer, BlockPos controllerPos, BlockSelection blockSel)
    {
        blockSel.Block = this;
        if (MachineConstructAccess.TryConstructInteract(world, byPlayer, controllerPos))
            return true;

        var be = world.BlockAccessor.GetBlockEntity(controllerPos);
        var construct = be?.GetBehavior<MachineConstruct>();
        if (construct != null && construct.HasConstruction && !construct.IsReady)
        {
            (world.Api as ICoreClientAPI)?.TriggerIngameError(this, "incomplete",
                Lang.Get("mymod:mymachine-structure-incomplete"));
            return true;
        }

        if (be is BlockEntityOpenableContainer openable)
            openable.OnPlayerRightClick(byPlayer, blockSel);
        return true;
    }
}
```

Остальные методы `IMultiBlockInteract` пустые, как в `BlockEHammer`. `MBOnPickBlock` и `MBGetPlacedBlockInteractionHelp` переводят позицию на контроллер и вызывают поведение контроллера: средний клик по призраку ничего не берёт, подсказка этапа видна с любого dummy.

## 3. Block entity

Рабочий тик, энергия, анимация и лишние меши включаются только у собранной машины.

```csharp
public bool StructureComplete
{
    get
    {
        var construct = GetBehavior<MachineConstruct>();
        if (construct != null && construct.HasConstruction)
            return construct.IsReady;
        return true;
    }
}

public bool IsFormed => Block?.Variant?["state"] == "formed";
```

В тике: `if (!IsFormed) return;`. Аниматор создаётся после перехода на `formed`.

Если у block entity свой `OnTesselation`, призрак отдаётся сборке. `base.OnTesselation` обязателен: именно поведение `MachineConstruct` рисует призрак и этапы и отключает обычный шейп блока.

```csharp
public override bool OnTesselation(ITerrainMeshPool mesher, ITesselatorAPI tesselator)
{
    var construct = GetBehavior<MachineConstruct>();
    if (construct is { IsRenderingBlueprint: true })
        return base.OnTesselation(mesher, tesselator);

    // свои меши жидкости и предметов — только у formed
    return base.OnTesselation(mesher, tesselator);
}
```

## 4. Строки

В `lang/ru.json` и `en.json`:

- `mymachine-handbook-place-controller` — подпись пустого первого этапа.
- `mymachine-construct-frame`, `mymachine-construct-finish` — те же ключи, что в `actionLangCode`. Они видны в подсказке блока.
- `mymachine-structure-incomplete` — ошибка, если кликнуть по неготовой машине без нужного ресурса.

Ключ `actionLangCode` пишется полностью, с доменом: `mymod:mymachine-construct-frame`.

## Что видит игрок

1. ПКМ книгой чертежей в воздухе — выбор схемы.
2. ПКМ по блоку — ставится `incomplete` лицом к игроку, multiblock сразу заполняет объём.
3. ПКМ по любому куску с ресурсом текущего этапа списывает его и меняет шейп.
4. Последний этап с `formMachine` ставит `formed` и пересобирает dummy.
5. Слом возвращает только сданные ресурсы.
